# DNMS - Codebase Overview

> Generated from a full read of the repository on 2026-09-14. Every number below was measured
> (file counts, route counts, line counts) rather than estimated. Companion document:
> `docs/codebase-audit-2026-09-14.md` (findings and recommendations).

DNMS ("Digitally Next Management System") is a multi-tenant company-management platform:
HR (employees, documents, org chart), biometric attendance (Hikvision devices), leave and WFH,
payroll, performance reviews, recruitment and referrals, a full project workspace (tasks,
goals, deliverables, drive, mailer, SEO, monitoring), a client portal, team chat, a
noticeboard, and a public marketing site with self-service signup.

**Key numbers**

| Metric                             | Value                                                       |
| ---------------------------------- | ----------------------------------------------------------- |
| Source files (ts/tsx, non-test)    | 1,184                                                       |
| Pages (`page.tsx`)                 | 95 (72 dashboard, 11 marketing, 6 auth, 10 portal/platform) |
| API route files (`route.ts`)       | 330                                                         |
| Feature folders (`features/*`)     | 29                                                          |
| Shared components                  | 47 `shared/` + 6 `layout/` + 6 `providers/` + 23 `ui/`      |
| Prisma models / enums              | 131 / 42 (315 `@@index`, 59 `@@unique`)                     |
| Migrations                         | 110                                                         |
| Client components (`"use client"`) | 336 files (49 of them are `page.tsx`)                       |
| Tests                              | 9 files, 282 tests (vitest, pure modules only)              |

## 1. Tech stack

- **Next.js 16** (App Router, Turbopack, `proxy.ts` instead of `middleware.ts`) + **React 19** + TypeScript (strict, `tsc --noEmit` is clean)
- **Prisma 7** on PostgreSQL through `@prisma/adapter-pg` (`pg` Pool, max 20 in production)
- **Auth.js v5 (next-auth beta)** - JWT sessions, one login for staff and clients
- **Tailwind CSS v4** + shadcn/ui (Radix primitives) + `lucide-react` icons
- **TanStack Query v5** (client data), **Zod v4** (validation), **react-hook-form**, **Zustand** (4 small stores)
- **recharts** (charts), **motion** (landing-page animation), **react-day-picker** (calendars)
- Integrations: Google APIs (Drive, GA4, Search Console), AWS S3 SDK (Backblaze B2 storage), nodemailer (SMTP / Brevo relay), web-push, AI providers (Mistral / Groq / OpenRouter / Gemini / Cerebras keys), Hikvision attendance devices
- Server-side document generation: `exceljs`, `docx`, `pptxgenjs` (deliverables reports), `xlsx` (imports/exports), `pdf-parse` + `mammoth` (brand-brief text extraction), `sharp` (photo/logo resizing)
- Tooling: pnpm, ESLint 10 (flat config, `eslint-config-next`), Prettier + tailwind plugin, vitest, tsx

## 2. Repository layout

The project follows `CLAUDE.md` (feature-based layout) with one deliberate difference: **there is
no `src/` folder** - `app/`, `features/`, `components/`, etc. sit at the repository root and the
path alias is `@/* -> ./*`.

### Conventions that hold across the tree

- `app/**/page.tsx` renders a feature component or a co-located `*-client.tsx`; API routes are thin.
- Feature barrels (`features/<x>/index.ts`) export components, hooks, schemas and pure `lib/`
  helpers only. **Server modules are imported directly by API routes** (documented in each barrel).
- Server code starts with `import "server-only"`; the guarded Prisma client is `db` from
  `@/server/db` (tenant-scoped by the `tenantGuard` extension).
- API responses use `ok()` / `fail()` from `lib/api-response.ts`; most routes are wrapped in
  `withAuth(permission, handler)`, `withSession`, `withClientSession`, `withCron` or `withErrorHandler`.
- Navigation is data-driven from `config/nav.ts` and gated by permission scopes.
- Files are kebab-case; components are PascalCase exports.

## 3. Surfaces and dashboard types

DNMS has **five distinct surfaces**, each with its own layout, navigation and audience.

| Surface          | Route group / prefix              | Audience                                          | Layout / shell                                                                                         |
| ---------------- | --------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Marketing site   | `(marketing)` - `/`, `/about`, …  | Anonymous visitors, search engines                | `MarketingHeader` + `MarketingFooter`, own scroll container, JSON-LD structured data                   |
| Auth             | `(auth)` - `/login`, `/signup`, … | Anyone signing in / up                            | Minimal `AuthShell`                                                                                    |
| Tenant dashboard | `(dashboard)` - `/{tenant}/…`     | Staff of one company                              | `Sidebar` (desktop) / `MobileTabbar` + "More" (phone), `Topbar`, `AiAssistant`, realtime notifications |
| Client portal    | `(portal)` - `/{tenant}/portal/…` | A customer's client users                         | `PortalSidebar` / `PortalTopbar` / `PortalMobileTabbar`, per-project modules                           |
| Platform console | `/platform`                       | DNMS staff (`admin_` role in the founding tenant) | Same chrome as the dashboard but `PlatformSidebar` (its own nav, no tenant items)                      |

### 3.1 Tenant dashboard - what a user sees depends on role

The home page `/dashboard` is one route that renders **one of two panels** (chosen in
`DashboardClient` from `usePermissions()`, and pre-fetched on the server with `HydrationBoundary`):

| Panel                | Component (`features/dashboard`) | Who                                  | Content                                                                                                                                 |
| -------------------- | -------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Employee dashboard   | `EmployeeDashboard`              | Everyone without `employee:read`     | Due Today / Overdue / In Progress tasks, Present This Month, Leave Available, Pending Requests, recent payslips, upcoming holidays      |
| Admin / HR dashboard | `AdminDashboard`                 | `employee:read` (+ `dashboard:read`) | Total Employees, New This Month, Total Documents, Unread Notifications, department pie chart, employee-status bar chart, recent joiners |

The **sidebar** (`config/nav.ts`) is built from five groups; a group only appears if the user holds
the gating scope:

| Group    | Items                                                                                                                                                                                                                                                                                                                                           | Gate                                                               |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Employee | Dashboard, My Attendance, My Leave, My Payslips, My Performance, Work From Home, Holiday Calendar, My Referrals, Notifications                                                                                                                                                                                                                  | none (every signed-in user)                                        |
| Company  | Chat, Announcements, Photo Gallery, Documents, Organisation Chart                                                                                                                                                                                                                                                                               | none                                                               |
| Project  | My Projects, My Tasks, Progress / My Progress, Clients                                                                                                                                                                                                                                                                                          | none; Clients needs `client:read`                                  |
| HRMS     | Employees (Directory, Departments, Designations, Job Roles), Resignations, Attendance (Directory, Devices), Holiday Calendar (manage), Leave (Directory, Types & Policy), Work From Home (requests), Payroll (Directory, Salary Structures), Performance (Evaluations, KPI Profiles), Recruitment (Careers, Applications, Referrals), Analytics | per-item `*:write` / `*:approve` / `*:review` / `*:read` scopes    |
| Admin    | Roles & Permissions, Audit Log, Email Templates, Integrations, Storage                                                                                                                                                                                                                                                                          | `role:read`, `audit:read`, `email_template:read`, `settings:write` |

Other dashboard-type screens inside the tenant app:

- **Project workspace** `/projects/[id]` - a 604-line client page with **19 lazily loaded tabs**:
  Brand, Content Calendar, Drive, Insights, Goals (+ overview card), Deliverables, SEO (+ sites
  card), Teams, Tasks, Requirements, Activity, Messages, Passwords, Clients, Mailer, Monitoring,
  plus Integration and Resources. Each tab is a feature component (see §6 "projects", "seo",
  "project-mailer", "monitoring", "client-portal").
- **Progress views** `/projects/progress` (portfolio / team / member progress, KPI drill-downs)
  and `/projects/[id]/deliverables/[period]` (a period's deliverables sheet).
- **Analytics** `/analytics` - org-wide charts (`AnalyticsCharts`, `analytics:read`).
- **Directories**: employee, attendance, leave, payroll directories are the HR "manage" screens;
  the matching `/…/me` pages are the employee's own view of the same data.
- **Help centre** `/docs` - in-app guides (Getting Started, Attendance, Documents, Employees,
  Leave, Payroll, Admin) rendered from `features/docs`.
- **Mobile**: on phones the sidebar is replaced by a five-tab bar; everything else lives under
  `/more` (`MobileMoreMenu`).

### 3.2 Client portal

`/portal` lists the projects a client user has been granted; `/portal/[projectRef]` opens a project
with modules resolved per grant (`features/client-portal/modules.ts` - `CLIENT_MODULES`):
overview, **activity** log, **channels** (messages), **inventory**, **mailer**, **products**.
First-time clients land on `/portal/set-password`.

### 3.3 Platform console

`/platform` (server-rendered, `force-dynamic`) lists every tenant with plan / status / headcount
totals (`features/tenants/server/platform.queries.ts`). Anyone who is not a platform admin gets a
**404**, not a 403 (so the route's existence is not confirmed).

## 4. Identity, tenancy and permissions (summary)

Full detail: `docs/identity-and-roles.md`, `docs/multi-tenancy-progress.md`.

- **One global `users` row per person** (email + password hash); `memberships` connect a user to a
  tenant as `STAFF` (→ `employees` profile) or `CLIENT` (→ `client_users` profile). A person with
  several memberships picks one at `/select-workspace`.
- **Tenant URL scheme** (`proxy.ts`, `lib/tenant-url.ts`): pages live at `/{tenantSlug}/…`
  (e.g. `/digitallynext/projects`); the proxy verifies the slug against the JWT, rewrites to the
  un-prefixed route and sets `x-tenant-slug` / `x-tenant-id` headers. Un-prefixed links are
  redirected to the canonical prefixed URL. APIs stay at `/api/…` and read the tenant from the token.
- **Data isolation**: every tenant-scoped table has `tenant_id`; the Prisma client is extended with
  `server/tenant-guard.ts`, which scopes every query and refuses unscoped ones
  (`runUnscoped(reason)` is the explicit escape hatch).
- **Roles** (per tenant, editable): `admin_` (DNMS staff, hidden), `admin`, `hr_manager`,
  `hr_employee`, `employee` - defined once in `lib/role-catalogue.ts` and used by both seeding and
  tenant provisioning. **Permissions** are 39 platform-level scopes (`lib/constants.ts`
  `PERMISSIONS`), checked with `hasPermission()` (`lib/permissions.ts`), `withAuth()` on the
  server and `usePermissions()` on the client. `admin_`/`admin` hold every scope; the difference is
  that only `admin_` (in the founding tenant, or an email in `PLATFORM_ADMINS`) reaches `/platform`.

## 5. User journeys

### 5.1 New company (self-service signup)

`/signup` (`features/tenants` `SignupForm`) → `createWorkspace()` server action (3 signups/hour/IP
throttle) → `provision.service.ts` creates the tenant, the five roles from the catalogue, the
founder as `admin` → sign-in → `/{slug}/dashboard`.

### 5.2 Staff sign-in

`/login` (`LoginForm`, one form for staff and clients) → Auth.js credentials → JWT carries
`kind`, `tenantId`, `tenantSlug`, `permissions`, `roles`, `mustChangePassword` →

- one membership: straight to `/{slug}/dashboard` (or `callbackUrl`)
- several memberships: `/select-workspace` (`WorkspacePicker`)
- `mustChangePassword`: the proxy funnels every request to `/change-password` (staff) or
  `/portal/set-password` (clients) until it is cleared
- deactivated account (e.g. approved resignation): `(dashboard)/layout.tsx` re-reads `isActive`
  on every navigation and renders `AccountDeactivated`.

### 5.3 Forgot password

`/forgot-password` → `POST /api/password/forgot` (emails an OTP) → `verify-otp` (returns a
short-lived reset token) → `reset`. These three endpoints are the only password routes that bypass
the session guard; all are rate-limited (`lib/rate-limit.ts`).

### 5.4 Client user

Invited by staff from a project's **Clients** tab or `/projects/clients/[id]` → invitation email →
`/login` → proxy sends `kind === "client"` to `/portal` → `/portal/set-password` on first login →
`/portal/[projectRef]/{activity|channels|inventory|mailer|products}` depending on grants. Staff
are kept out of `/portal` and clients out of the dashboard by the proxy and again by each layout.

### 5.5 Employee - a typical day

Dashboard (due / overdue tasks) → **My Attendance** (`/attendance/me`, device punches synced from
Hikvision, GPS check-ins, floating-holiday picks) → **My Tasks** / a project's Tasks tab (log work,
clock, status with reason) → **Chat** (SSE stream, reactions, polls, voice notes) → **Notifications**
(in-app SSE + web-push via `sw.js`) → **Apply leave / WFH** (`/leave/apply`, `/wfh/apply`, with
AI "polish reason") → **My Payslips** (`/payroll/me`) → **My Performance** (self-assessment).

### 5.6 HR manager

**Employee Directory** → `/employees/new` (`EmployeeForm`: personal, employment, salary, roles,
documents, avatar) → **Documents** & document requests (expiry cron) → **Attendance Directory**
(manual corrections, device sync, floating holidays) → **Leave Directory** (approve/reject with
`LeaveDecisionDialog`, balances, policy matrix, accrual/rollover crons) → **WFH requests** →
**Payroll Directory** (`GeneratePayrollDialog` from salary structures, statutory deductions) →
**Performance** (evaluation cycles auto-created by cron, KPI profiles) → **Resignations** (review,
approval deactivates the account) → **Recruitment** (careers openings, public applications via
`/api/public/careers`, interviews, referral rewards) → **Announcements / Gallery**.

### 5.7 Project / account manager

`/projects` → create project (`ProjectFormDialog`, logo, six fixed teams: WEB, DESIGN, MAP, VIDEO,
AMG/SMO, ADMIN - `features/projects/lib/project-teams.ts`) → **Teams** (staffing, managers) →
**Requirements** → **Goals** (tree, targets, tags) → **Tasks** (sheet view, timeline, follow-ups,
reminders) → **Deliverables** per period (plan, log, history, owed panel; export XLSX / DOCX /
PPTX report) → **Drive** (Google Drive folders / B2 storage) → **Brand** (AI brief analysis from
PDF/DOCX) → **Content Calendar** / **Meta sync** → **SEO** (sites, keywords, scorecard, technical
audit, backlinks, competitors, GA4 / GSC / PSI, IndexNow) → **Mailer** (campaigns to imported
recipients, in-process runner) → **Monitoring** (uptime probes, incidents, escalation) →
**Messages** (project channel, SSE) → **Clients** (portal access grants) → **Insights** / **Progress**.

### 5.8 Platform admin (DNMS staff)

Sign in to the founding workspace → `/platform` (tenants, plans, totals) → back to own workspace via
`PlatformSidebar`.
